# Session Log — 2026-07-08

## Summary
Fixed the exercise sub/swap feature which was completely broken and invisible.

## Root Causes Found (3 separate bugs)

### Bug 1 — Sub button invisible in light mode
The ⇄ Sub button had hardcoded white CSS (`color:rgba(255,255,255,0.5)`, `background:rgba(255,255,255,0.07)`) — invisible on a light background. User reported "there is no Sub button." Fixed to use CSS variables: `color:var(--muted)`, `background:var(--s3)`, `border:var(--border)`.

### Bug 2 — S.exSwaps not in initial state (TypeError crash)
`S.exSwaps` was referenced in the "coming up" section but never declared in the initial `let S={...}` object. This caused a TypeError crash whenever rendering a workout that had upcoming exercises. Added `exSwaps:{}` to the S init and added a null guard `(S.exSwaps&&S.exSwaps[k])` in the coming-up template.

### Bug 3 — swapExercise() mutating WK const (v34 fix never landed in file)
The supposed v34 fix (use `S.exSwaps` map instead of mutating `WK`) was NOT in the file — old code was still there doing `getWorkoutDay(S.day).exercises[S.exIdx]=swapped` which breaks on re-render. Properly fixed:
- `curEx()` now checks `S.exSwaps[day+'_'+exIdx]` first
- `swapExercise()` stores swap in `S.exSwaps` (no WK mutation)
- Uses `data-sid` attribute on alt buttons to avoid JS quote-escaping issues
- Fixed `_swappedFrom` → `_subbedFrom` property name (badge now shows)
- `selectDay()` now resets both `S.exSwaps={}` and `S.extraSets={}`
